# E04 — Math-Aware Chunking & Content-Addressable IDs (Tier 1c)

**Epic dependencies:** E03.

**Goal:** replace the naive `\section`-only chunker with the six-rule, math-aware chunker from `04-parsing-and-chunking.md`. Theorem+proof pairing, equation atoms, hierarchical levels (paper / section / theorem), per-paper preamble prepended to every chunk, content-addressable IDs. The chunker is versioned and its output is the boundary that storage (E05) and retrieval (E06) read from.

**Effort:** 1–2 weeks.

**References:** `04-parsing-and-chunking.md` § Chunking strategy for research-math papers (the six rules), § What gets stored per chunk, § Equation atom record, § Chunker versioning; `02-architecture-overview.md` § Determinism contract.

### E04_S01 — Theorem-environment detector and statement extractor

**Description.** Implement Rule 1 from `04-parsing-and-chunking.md`: detect `theorem`, `lemma`, `proposition`, `corollary`, `definition`, `remark`, `example` environments in the normalized HTML and extract each statement as a candidate chunk. Authors redefine these via `\newtheorem`; the detector must follow the redeclarations.

**Acceptance criteria.**
- [ ] `ingest/chunker/theorem_detect.py::detect(normalized: NormalizedPaper) -> list[TheoremCandidate]`.
- [ ] Picks up amsthm-style environments and their author-redefined names (e.g. a paper that does `\newtheorem{thm}{Theorem}` and uses `\begin{thm}...\end{thm}`).
- [ ] Each candidate carries label (`Theorem 3.4`), environment kind, char offsets, and section path.
- [ ] Test fixture: a paper with 5 theorems and 2 lemmas yields 7 candidates with correct labels.
- [ ] Counter `arxmcp_chunker_theorems_detected_total` exposed for E14 metrics scaffolding.

**Dependencies.** none within E04.

**Complexity.** M.

**Labels.** `area:parser`, `kind:feature`.

### E04_S02 — Pair theorems with their following proofs

**Description.** Per Rule 1, pair each theorem-like environment with the immediately-following `proof` environment into a single chunk (`kind = theorem_with_proof`). If the proof is >2000 tokens, keep the statement chunk separately and prepend it as a header to each proof sub-chunk. Bare theorem statements (no proof) get `kind = theorem_only`.

**Acceptance criteria.**
- [ ] `ingest/chunker/pair_theorem_proof.py::pair(candidates, normalized) -> list[PairedChunk]`.
- [ ] Theorem followed by `proof` within ≤1 paragraph: paired into a `theorem_with_proof` chunk.
- [ ] Theorem with no following proof: standalone `theorem_only` chunk.
- [ ] Long proof (>2000 tokens, measured via tiktoken or fallback char/4): split into `proof_part_1`, `proof_part_2`, ... each with the theorem statement prepended as a header.
- [ ] Test: synthetic proof of 3000 tokens splits into 2 sub-chunks with the statement prepended on both.
- [ ] Test: orphan `proof` environment with no preceding theorem is logged as a chunker warning, not a crash.

**Dependencies.** E04_S01.

**Complexity.** L.

**Labels.** `area:parser`, `kind:feature`.

### E04_S03 — Display equation atom extraction

**Description.** Implement Rule 3 from `04-parsing-and-chunking.md`: every numbered display equation gets its own retrievable record per the equation-atom schema. ASCII form for keyword/BM25 fallback, MathML as canonical, presentation LaTeX for human display, plus the surrounding sentence as context.

**Acceptance criteria.**
- [ ] `ingest/chunker/equation_atoms.py::extract(normalized: NormalizedPaper) -> list[EquationAtom]`.
- [ ] Each atom has `equation_id` (content-addressable), `paper_id`, `label`, `presentation_latex`, `mathml`, `ascii_form`, `context_sentence`, `is_numbered`, `is_display`, `parent_chunk_id` placeholder.
- [ ] ASCII form is generated by an existing tool (e.g. `unicode-it`, `latex2sympy2`) — pinned dependency.
- [ ] Inline equations and unnumbered displays are NOT extracted as atoms — only numbered displays.
- [ ] Test: fixture with 4 numbered equations and 12 inline equations yields exactly 4 atoms.
- [ ] Test: equation atom `equation_id` is reproducible across runs (determinism).

**Dependencies.** none within E04.

**Complexity.** L.

**Labels.** `area:parser`, `kind:feature`.

### E04_S04 — Hierarchical level emitter (paper / section / theorem)

**Description.** Implement Rule 5 from `04-parsing-and-chunking.md`: index every paper at three levels — paper (abstract + section list + key terms), section (1–2 paragraph summary + chunk pointers), theorem (statement + proof + preamble). Different agent roles query different levels.

**Acceptance criteria.**
- [ ] `ingest/chunker/levels.py` emits chunks at three `level` values: `paper`, `section`, `theorem`.
- [ ] `paper`-level chunk: `embedding_text` = title + abstract + section headings list + author macro definitions summary.
- [ ] `section`-level chunk: `embedding_text` = preamble header + section text (excluding theorem environments, which exist as their own theorem-level chunks).
- [ ] `theorem`-level chunks: come from E04_S02 (paired) plus any standalone definitions/remarks the user wants retrievable.
- [ ] Test: fixture paper with 3 sections and 5 theorems yields 1 paper-level + 3 section-level + 5 theorem-level chunks.
- [ ] Section-level summarization is template-based for v1 (first 200 chars + last 200 chars + theorem labels listed); LLM summarization is deferred to a later issue.

**Dependencies.** E04_S02.

**Complexity.** M.

**Labels.** `area:parser`, `kind:feature`.

### E04_S05 — Per-paper preamble prepended to every chunk's embedding text

**Description.** Wire the preamble extracted in E03_S03 into every chunk's `embedding_text` field per Rule 2 — "the single biggest retrieval-quality lever after macro expansion." The preamble is prepended; the chunk body follows; both are joined with a fixed separator.

**Acceptance criteria.**
- [ ] `ingest/chunker/embed_text.py::compose(preamble, body_canonical) -> str` emits a deterministic byte sequence.
- [ ] Separator: `\n\n--- chunk body ---\n\n` (frozen).
- [ ] Preamble is truncated to 1024 tokens before composition (already enforced in E03_S03).
- [ ] Test: composing the same `(preamble, body_canonical)` twice yields byte-identical strings.
- [ ] Documented in module docstring as the contract the embedder reads.

**Dependencies.** E04_S04, E03_S03.

**Complexity.** S.

**Labels.** `area:parser`, `area:embedder`.

### E04_S06 — Content-addressable chunk IDs

**Description.** Implement Rule 6 from `04-parsing-and-chunking.md`: chunk IDs are `arxiv:<paper_id>:<sha256(canonical_chunk_bytes)[:16]>`. Editing a chunk produces a new ID. The canonical bytes are the deterministic composition from E04_S05 plus the structural metadata (level, kind, label).

**Acceptance criteria.**
- [ ] `ingest/chunker/ids.py::compute_chunk_id(chunk_record) -> str`.
- [ ] Format: `arxiv:<paper_id>:<sha256(canonical_bytes)[:16]>` exactly.
- [ ] `paper_id` is the canonical arXiv ID without version suffix; version is a separate field.
- [ ] Two versions of the same paper produce two distinct chunk IDs because the body bytes differ.
- [ ] Test: identical chunks across two runs produce identical IDs; mutating any field except `created_at` changes the ID.
- [ ] Test: the 16-char hash collision space is documented (≤1 expected collision per ~10^9 chunks; we have ~5M).

**Dependencies.** E04_S05.

**Complexity.** S.

**Labels.** `area:parser`, `area:cache`, `kind:feature`.

### E04_S07 — Cross-reference back-fill into `referenced_chunks`

**Description.** After all chunks have IDs (E04_S06), run a back-fill pass that resolves the cross-references identified in E03_S04 to actual `chunk_id`s and populates `referenced_chunks` on each chunk. Two-pass: pass 1 builds a `(paper_id, label) -> chunk_id` map; pass 2 walks every chunk and rewrites pointers.

**Acceptance criteria.**
- [ ] `ingest/chunker/xref_backfill.py::backfill(chunks) -> chunks` returns a list with `referenced_chunks` populated.
- [ ] Pointers that fail to resolve (e.g. `\ref` to a label that doesn't exist) are dropped silently per `04-parsing-and-chunking.md` § Failure modes.
- [ ] Test: fixture with `Theorem 1` referenced by `Theorem 3` produces `chunks[2].referenced_chunks == [chunks[0].chunk_id]`.
- [ ] Idempotent: running back-fill twice produces identical results.
- [ ] `equation_atoms[].parent_chunk_id` populated in the same pass.

**Dependencies.** E04_S03, E04_S06.

**Complexity.** M.

**Labels.** `area:parser`, `kind:feature`.

### E04_S08 — Chunk persistence with sharded layout

**Description.** Persist chunks as JSON to `var/arxmcp/corpus/chunks/<sha256[:2]>/<chunk_id>.json` per `03-ingestion-pipeline.md` § What gets stored on disk. Sharded by the first byte of the SHA so directory listings stay manageable at scale.

**Acceptance criteria.**
- [ ] `ingest/chunker/persist.py::write_chunks(chunks)` writes one JSON file per chunk under the sharded path.
- [ ] Equation atoms persist similarly under `var/arxmcp/corpus/equations/<sha256[:2]>/<equation_id>.json`.
- [ ] Atomic write (`.tmp` then rename).
- [ ] Read-side helper `load_chunk(chunk_id)` is symmetric.
- [ ] Test: writing and re-reading 100 fixture chunks gives identical bytes.
- [ ] On disk size sanity: 5K seed chunks fit in <50 MB.

**Dependencies.** E04_S07.

**Complexity.** S.

**Labels.** `area:storage`, `kind:feature`.

### E04_S09 — Chunker version bump test (frozen hash)

**Description.** Per `04-parsing-and-chunking.md` § Chunker versioning, every chunker change is a version bump. Add a CI test that runs the chunker on a frozen 3-paper fixture and asserts the SHA-256 of the sorted output matches a checked-in constant. Any meaningful change requires updating the constant — forcing reviewers to acknowledge the chunker version bump.

**Acceptance criteria.**
- [ ] `tests/chunker/test_frozen_output.py` runs the full pipeline on 3 fixture papers (committed under `tests/fixtures/papers/`).
- [ ] Computes SHA-256 over the sorted JSON of all emitted chunks + equation atoms.
- [ ] Asserts the hash equals a constant in `ingest/chunker/version.py::CHUNKER_OUTPUT_HASH_V1_0`.
- [ ] CI fails on any unintended divergence; PR description must explain the bump.
- [ ] Documented bump procedure in `docs/chunker-versioning.md`.

**Dependencies.** E04_S08.

**Complexity.** S.

**Labels.** `area:parser`, `kind:infra`, `area:cache`.

### E04_S10 — Long-proof multi-chunk header injection

**Description.** Edge case from E04_S02: when a single proof is split into multiple sub-chunks, each sub-chunk needs the theorem statement injected as a header so retrieval against `proof_part_3` still surfaces the right context. Verify and harden this via tests.

**Acceptance criteria.**
- [ ] Each `proof_part_*` sub-chunk's `embedding_text` starts with the theorem statement (truncated to 256 tokens), then a separator, then the proof part.
- [ ] All `proof_part_*` chunks carry the same `parent_theorem_chunk_id` field.
- [ ] Test: fixture with a 4000-token proof splits into 2 sub-chunks; both have the theorem statement as the leading 256 tokens of `embedding_text`.
- [ ] Test: BM25 query for a term that appears only in the theorem statement (not the proof body) returns all sub-chunks.

**Dependencies.** E04_S02, E04_S05.

**Complexity.** S.

**Labels.** `area:parser`, `area:retrieval`.

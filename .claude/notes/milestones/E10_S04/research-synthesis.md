# E10_S04 — Research Synthesis

Merged from [research-brief-1.md](research-brief-1.md) (doc-layout +
LaTeXML invocation deep-read) and [research-brief-2.md](research-brief-2.md)
(empirical LaTeXML output + ops scenario trace). Researcher 2's live
verification of the LaTeXML output structure is the most consequential
empirical finding — raw HTML is NOT byte-stable, only extracted
`<math>` elements are.

## 1. Headline findings (consensus)

| # | finding | resolution |
|---|---|---|
| 1 | **Raw LaTeXML HTML is NOT byte-stable across runs of the same version.** Researcher 2 verified two consecutive `latexmlc` runs differ at TWO locations: an HTML comment with a generation timestamp AND a visible `<div class="ltx_page_logo">` containing the timestamp. `--nocomments` only suppresses the XML comment, not the div. | **The drift detector MUST extract `<math>` elements from the HTML output before diff.** Reuse the same BS4 `find_all("math")` + `str(tag)` pattern as `ingest/extract_equations.py::_serialize_mathml`. Raw HTML diff is unworkable. |
| 2 | The equations table is EMPTY in the seed corpus (per E10_S03b finding). | **Use checked-in fixture MathML files as the baseline, NOT the live equations table.** The brief's "compare against stored values in the equations table" path is unreachable at v1. |
| 3 | LaTeXML's tikz-cd output is SVG-based, not MathML. The labels inside arrows are nested `<math>` elements inside `<foreignObject>`. | **Drop tikz-cd from v1 fixtures.** Replace with `\begin{pmatrix}` matrix notation — covers a different complexity axis (multi-row/multi-column) without the tikz-cd brittleness. The 5 fixture types become: simple fraction, integral, summation, multi-line align, matrix. |
| 4 | `latexmlc` is fast on small standalone `.tex` files. Researcher 2 measured `frac.tex` at <1 second; 5 fixtures total < 5 seconds. | Timeout per fixture: **15 seconds** (Researcher 2). Tight enough to detect hangs, ample headroom for slow CI. Total wall time for 5 fixtures: < 75s. |
| 5 | The runbook's `python -m ingest.index_equations --rerender-all` flag does NOT exist (Researcher 1 verified). The brief conflates two operations: re-rendering TeX→MathML (`ingest.extract_equations`) and rebuilding the TED tree (`ingest.index_equations`). | **Update the runbook to invoke both modules correctly.** No new `--rerender-all` flag; just call both modules in sequence. |
| 6 | No `ops/` directory exists today. | Create `ops/cron/` and `ops/drift_check.py` (the Python entry point). |

## 2. Disagreement and resolution: doc placement

The most consequential disagreement.

- **Researcher 1**: `.claude/docs/ops/latexml-drift-runbook.md` — strict
  interpretation of the doc-layout rule ("ONLY user-facing referenced
  from root README").
- **Researcher 2**: `docs/ops/latexml-drift-runbook.md` with a brief
  Operations section added to the root README linking it — operator
  runbooks belong in `docs/`, and the rule's exception is satisfiable
  by updating the README.

### Resolution: `docs/ops/latexml-drift-runbook.md` + root README link

Pick Researcher 2's recommendation. Three reasons:

1. **The runbook IS operator-facing** — humans run it after a cron
   alert fires. That is exactly what the doc-layout rule's exception
   ("operator-facing AND linked from root README") was written for.
2. **Sustainability** — E14 (observability/ops) is on the roadmap and
   will produce more runbooks. Establishing `docs/ops/` now means E14
   adds files alongside rather than relocating.
3. **The brief is explicit.** The brief proposes
   `docs/ops/latexml-drift-runbook.md` AND `docs/ops/cron-jobs.md`.
   Deviating without a compelling reason burns credibility on the
   roadmap's design intent.

**However:** `docs/ops/cron-jobs.md` is a registry of cron jobs — more
agent-internal coordination than operator procedure. Split it:

- `docs/ops/latexml-drift-runbook.md` — operator procedure for a real
  alert; link from root README.
- `.claude/docs/ops/cron-jobs.md` — internal registry of automated
  tasks; NOT linked from README.

The root README gains a minimal "Operations" section pointing at the
runbook. No other links.

## 3. Design decisions (D1–D14)

### D1. Drift baseline = hand-checked-in MathML fixture files

5 hand-crafted `.tex` files in `tests/fixtures/latexml-drift/` paired
with `.expected.mathml` files containing the extracted-and-serialized
`<math>` elements. The expected file is regenerated by an
operator-invoked `--update-fixtures` flow (D8).

### D2. Diff happens on extracted `<math>` elements, byte-for-byte

After running `latexmlc` and reading the HTML, the drift detector:
1. Parses the HTML via `BeautifulSoup(html, "html.parser")`.
2. Walks `soup.find_all("math")` and serializes each via
   `str(tag)`, joining with `\n` for a stable canonical form.
3. Compares this string byte-for-byte against the checked-in
   `.expected.mathml` file.

**No pretty-printing.** Researcher 1 explicitly recommended byte-for-
byte; Researcher 2 suggested pretty-printing for better error messages
but flagged the canonicalization concern. Pick byte-for-byte at v1 —
on first drift, the operator inspects the diff via `git diff`-style
tooling; pretty-printing can land in v2 if the diff proves unreadable.

### D3. 5 fixtures replace tikz-cd with pmatrix

```
tests/fixtures/latexml-drift/
├── frac.tex              \frac{a}{b}
├── integral.tex          \int_0^\infty f(x)\,dx
├── sum.tex               \sum_{n=0}^{\infty} a_n  (in equation env to lock <munderover>)
├── align.tex             \begin{align} a &= b \\ c &= d \end{align}
└── pmatrix.tex           \begin{pmatrix} a & b \\ c & d \end{pmatrix}
```

Each gets a paired `<name>.expected.mathml`. Drop tikz-cd per the
empirical finding that LaTeXML produces SVG (not MathML) for tikz-cd.

### D4. Cron script structure

`ops/cron/latexml-drift-check.sh` is a thin bash wrapper:

```bash
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")/../.."
exec /Users/chris.dare/Library/Python/3.9/bin/uv run python -m ops.drift_check "$@"
```

All logic lives in `ops/drift_check.py`. Bash is just the cron entry
point.

### D5. Python entry point — `ops/drift_check.py`

Top-level module exposing:

- `compare_fixture(name, fixture_dir)` — runs `latexmlc` on the
  named fixture, extracts MathML, returns `(actual_mathml, expected_mathml)`.
- `check_all_fixtures(fixture_dir) -> list[DriftResult]` — runs all
  5 fixtures, returns per-fixture results.
- `_cli(argv)` — handles `python -m ops.drift_check` with `--check`
  (default) and `--update-fixtures` flags.

### D6. Counter exposure — in-process Prometheus counter

Define `LATEXML_DRIFT_DETECTED_COUNTER` in `server/metrics.py`
(co-located with other counters; reachable for the test patch). The
drift detector imports it and `.inc()`s when drift is found.

The counter only increments inside the cron process — the live server
process never invokes the drift detector. **Production exposure via
the `/metrics` endpoint is deferred to E14** (the full observability
refactor). At v1 the operational signal is:
1. ERROR log to stderr (caught by cron mailer / systemd-timer logs).
2. Sentinel file `var/arxmcp/ops/drift-detected.flag` written on
   drift (operator clears manually after rectifying).
3. Non-zero exit code from the cron script.

The AC's "counter increments when drift detected (verifiable via test)"
is satisfied by a test that patches the counter and asserts it was
called.

### D7. Test strategy — mock-based fast tests + opt-in `requires_latexmlc` integration

- **Default suite (fast, no `latexmlc`)**: tests use the
  `.expected.mathml` fixtures as both the actual and expected sides
  with monkeypatched extractor outputs. Covers: diff logic, exit
  codes, sentinel file write, counter increment, `--update-fixtures`
  behavior.
- **Integration (slow, real `latexmlc`)**: marked
  `@pytest.mark.requires_latexmlc`. Loads the real fixture `.tex`,
  invokes `latexmlc`, compares against checked-in `.expected.mathml`.
  Skipped by default; opt-in via the marker. Mirrors the
  `requires_model` pattern from the BGE-M3 tests.

The cron job runs `python -m ops.drift_check`, NOT pytest. Pytest is
the test harness; the cron is production.

### D8. `--update-fixtures` flag

Operator workflow: after a LaTeXML upgrade and successful reindex, run

```
python -m ops.drift_check --update-fixtures
```

This re-renders all 5 fixtures and overwrites the
`<name>.expected.mathml` files. Operator then commits the changes.
Analogous to `pytest --update-tool-schema-hash`.

### D9. Timeout per fixture: 15 seconds

Empirically `latexmlc` on a 20-line `.tex` runs in < 1 second. 15s
catches hangs without false positives on slow CI. Module constant
`LATEXML_FIXTURE_TIMEOUT_SECONDS = 15` in `ops/drift_check.py`.

### D10. No new pyproject.toml deps

All required deps present: `subprocess` (stdlib), `pathlib` (stdlib),
`BeautifulSoup` (already in pyproject), `prometheus_client` (already
in pyproject). No additions.

### D11. Runbook updates `extract_equations` + `index_equations` correctly

Step 2 of the runbook becomes:

```
2a. Run `python -m ingest.extract_equations <paper_id>` for every
    paper in the corpus to re-render TeX → MathML via the new
    LaTeXML version. (Loops over papers; ~30 minutes for 50 papers.)
2b. Run `python -m ingest.index_equations` to rebuild the
    mathml_tree_json column from the new MathML.
```

NOT `python -m ingest.index_equations --rerender-all` (that flag
doesn't exist).

### D12. README "Operations" section added

A minimal new section in `README.md`:

```markdown
## Operations

For operator runbooks (drift detection, reindex flows), see
[docs/ops/](docs/ops/).
```

This is what unlocks the `docs/ops/` placement decision per the
doc-layout rule.

### D13. `cron-jobs.md` stays under `.claude/docs/`

Per the rule split in §2 — internal cron registry, not operator
procedure.

### D14. Sentinel file path follows existing `var/arxmcp/ops/` convention

`make bootstrap` already creates `var/arxmcp/ops/parser-failures/`.
The drift sentinel lives at
`var/arxmcp/ops/drift-detected.flag` (NOT inside a subdir — it's a
single flag file). The bootstrap path needs to ensure
`var/arxmcp/ops/` exists; verify.

## 5. Landmines

1. `assert` banned.
2. HEREDOC commits.
3. `uv run python -m pytest`.
4. GPG signing.
5. No `--no-verify`.
6. **Raw HTML is NOT byte-stable; extract `<math>` before diff.**
7. **`docs/ops/` requires a root README link to satisfy the rule.**
8. **`ingest.index_equations` does NOT have `--rerender-all`** —
   runbook uses `extract_equations` then `index_equations`.
9. **tikz-cd renders as SVG**, not MathML — dropped from v1 fixtures.
10. Cron + Pytest are different runtimes. Test the cron's logic via
    pytest mocks, but the cron runs `python -m ops.drift_check`.

## 6. Test surface

### AC coverage

- **AC1** — drift-check against current LaTeXML produces zero alerts.
  Integration test (`requires_latexmlc`) runs `latexmlc` on each
  fixture, asserts no drift detected.
- **AC2** — modifying a fixture's expected MathML causes script to
  exit non-zero. Mock-based test that monkeypatches the actual MathML
  to mismatch the expected; asserts the script raises / exits != 0.
- **AC3** — counter increments on drift. Patch
  `LATEXML_DRIFT_DETECTED_COUNTER` and verify `.inc()` was called.
- **AC4** — runbook includes timing estimates. Static test: read
  `docs/ops/latexml-drift-runbook.md`, assert specific phrases like
  "50-paper" and "200K" appear (low-value but pins the AC).

### Beyond-AC tests

- `--update-fixtures` rewrites all 5 expected files.
- The cron script's exit-code on no-drift is 0; on drift is non-zero.
- Sentinel file is written on drift; cleared on next clean run.
- Missing `latexmlc` raises `RuntimeError` (mirroring
  `parse_with_latexml`'s `shutil.which` guard).
- Fixture file with no `<math>` elements is a soft error (logged,
  doesn't trip counter — likely a fixture bug).
- BeautifulSoup parse of LaTeXML output is correct (verified via
  fixture).

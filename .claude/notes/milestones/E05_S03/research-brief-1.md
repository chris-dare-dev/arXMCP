### `tests/eval/test_retrieval_quality.py` — exact invocation

The brief's invocation is verbatim correct:
```
pytest tests/eval/test_retrieval_quality.py --ndcg-min=0.70
```
The `--ndcg-min` flag is registered in `tests/conftest.py:33-43`; default is `0.70`. The flag is consumed by the `ndcg_min` fixture (`tests/conftest.py:46-49`) and asserted in `assert_threshold(ndcg5_mean, ndcg_min)` inside `score_and_write` (`test_retrieval_quality.py:334`). On failure the test raises `tests.eval.metrics.ThresholdNotMetError` (subclass of `AssertionError`).

**Cold-start protocol** (load-bearing for AC writing): the test SKIPS — never fails — when the corpus marker is absent OR `queries.json` is empty (`test_retrieval_quality.py:159-174`). Quoting the module docstring:

> "The test SKIPs (does not fail) on every cold-start cell — `make test` must stay green on a fresh checkout. The Tier-0 exit gate (E05_S03) is the layer that asserts the prerequisites are present before this test runs."

That last sentence is **load-bearing**: E05_S03 is the contract that says "skip ≠ pass for promotion." `TIER-GATES.md` must call this out explicitly, otherwise an operator sees `passed in N seconds` from a skip-only run and falsely promotes.

## Open questions (with opinionated recommendations)

**(a) Where in `README.md` should the link go?** Insert a new `## Tier exit gates` section between **Hard constraints** and **Quick start**, containing one paragraph + the link. Add a `make eval` line to the Quick start code block. Rationale: the link must be visible above the fold for a contributor doing first-time orientation; burying it inside "Documentation" hides it next to design notes.

**(b) `make eval` target format.** Mirror `make test`: just invoke pytest. **No header echo, no summary print.** The expected-output documentation lives in `TIER-GATES.md`; a Make echo would duplicate it and drift. Use `$(PYTHON) -m pytest tests/eval/test_retrieval_quality.py --ndcg-min=0.70`. Add the same `MIN_PY_MINOR` guard the existing `test:` target uses (lines 42-44), so `make eval` on stale Python fails fast with a clear message. Also update `help:` to list it.

**(c) "Expected output" format.** A fenced code block per gate showing the **pass case** (`============ 1 passed in N.NNs ============`), the **fail case** (the `ThresholdNotMetError` traceback summary), and — critical — the **skip case** with a one-liner: *"a SKIP outcome is NOT a pass; the corpus + fixture must be in place before the gate is meaningful."* Don't fabricate exact wall-clock numbers; use `N.NN` placeholders.

**(d) Document the cold-start skip behavior?** Yes — briefly. One short paragraph under the Tier-0 row stating that the test SKIPS (not fails) when corpus or fixture is absent, and that skip ≠ pass for promotion. Cross-link to `docs/eval-curation.md` (curation prereq) and the future ingestion driver. Without this, the gate has a false-green failure mode.

**(e) Where does E01_S10 retirement land?** It is **already retired** in prose at `.claude/roadmap/E01-shipped.md:167` (which says `E05_S03` supersedes it). So no roadmap edit is needed. **In `TIER-GATES.md`**, add one short "History" section at the bottom: "This document replaces the qualitative Tier-0 'vibes-check' demo originally described in `.claude/notes/09-feature-priorities.md` and planned as `E01_S10` (which is not built)." That gives a single landing page for someone Ctrl-F'ing for "vibes-check" in 6 months.
